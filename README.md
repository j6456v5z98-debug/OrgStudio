## 2. 背景与目标

### 2.1 组织人事在 HCM 中的位置

`组织人事（Core HR / 组织与人员）是整个人力资本管理（HCM）套件的`**`数据与流程基座`**`：`

- `它维护「人 / 组织 / 岗位 / 任职 / 汇报关系」的`**`单一事实源`**`；`
- `下游的薪资、考勤、招聘、绩效、学习、分析，都以本模块的主数据为前提。`

`对标产品的共识：`**`没有稳固的 Core HR，就没有可信的 HCM`**`。Workday 强调"单一数据模型（人/组织/任职/业务事件）"，SuccessFactors 强调"单一已验证的 HR 数据来源（single source of truth）"——两者都把组织人事当作中台而非孤岛。`

### `2.2 对标缘由`

- **`SAP SuccessFactors（Employee Central）`**`：企业级 HRIS 的事实标准，强在组织建模、职位管理、全球合规与本地化、人事事件的最佳实践流程。`
- **`Workday Core HCM`**`：以"消费级体验 + 搜索优先 + 事务/分析同源"著称，强在灵活组织类型、重组/M&A 建模、配置化业务流程与统一安全模型。`
- `本产品希望`**`兼取两者之长`**`：SF 的严谨治理与合规深度 + Workday 的易用体验与配置弹性。`

### 2.3 范围边界（含 / 不含）

| 纳入本模块                                                                            | 仅留接口 / 边界说明（不在本文展开）                                              |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 组织 / 岗位 / 编制 / 人员主数据 / 汇报关系 / 组织版本 / 维度 / 人事事件 / 自助 / 搜索 / 核心分析 / 权限与安全 / 全球化本地化 | 薪资核算与发薪、考勤与时间管理、招聘与 onboarding、绩效与目标、学习与发展、薪酬激励（Compensation）、福利 |

> 澄清文档只负责把"边界"讲清楚；跨模块接口以 §5.11 / §8 的待决策项跟踪。

## 4. 整体设计原则

从两家提炼、作为本模块设计的底层约束：

1. **单一事实源（Single Source of Truth）**：组织、人员、岗位、任职只存一处，下游模块只读引用，杜绝多副本。
2. **搜索优先（Search-First）**：任何对象（人/组织/岗位）都应可被全局搜索直达，菜单是"兜底"而非唯一入口。
3. **消费级体验**：消费级 App 的易用标准 + 企业级的可信与治理，少层级、少点击、强反馈。
4. **配置化而非定制（Configure, not Customize）**：组织类型、档案页签、字段、业务流程、审批流均可配置，避免代码级二开。
5. **全球化、本地化（Global by Default, Local when Needed）**：可插拔本地化（语言/币种/日期/合规），核心模型全球一致。
6. **事务与分析同源**：交易数据与报表数据同库同源，报表可下钻回交易并就地操作。
7. **安全内建（Security by Design）**：基于"数据对象"而非"字段"的统一安全，叠加数据范围（可见子树）与字段级脱敏。

## 5. 功能需求

> 每条含：**功能描述 / 关键能力 / 业务流程要点 / 验收线索**。

### 5.1 组织管理（Organization Management）

- **功能描述**：维护企业的组织结构（公司、事业部、部门、团队等），提供多类型组织与交互式组织图。
- **关键能力**：
  - 组织单元 CRUD（新建/编辑/移动/关闭/合并）与唯一编码体系；
  - 多类型组织：法人实体、成本中心、部门、地点、矩阵/项目型组织；
  - 交互式组织图（树形/缩略），点击节点展开详情、支持拖拽式重组（reorg）建模；
  - 组织负责人（Manager）、层级深度、在编人数实时展示。
- **业务流程要点**：组织变更（更名/移动/新设/关闭）走"调整单 → 审批 → 生效"流程（见 5.5）。
- **验收线索**：可在组织图中拖拽部门并预览重组影响；关闭部门前系统阻止产生孤儿节点。

### 5.2 岗位与编制（Position & Headcount）

- **功能描述**：定义"岗位（Position）"这一组织需求单元，并管理编制（Headcount）。
- **关键能力**：
  - **岗位 vs 职位（Job）分离**：Job = 职级/职能类别（如"高级工程师"），Position = 具体空缺/占用实例（如"研发部·高级工程师#1"）；
  - 岗位继承 Job 的职级/职能/薪酬带宽，支持关键岗位（Critical Position）标记；
  - 编制计划（年度/季度）、在编/空缺/超编实时计算、满编拦截。
- **业务流程要点**：空缺岗位可触发招聘需求（接口到招聘模块）；岗位变更联动任职与编制校验。
- **验收线索**：新建岗位自动带出 Job 的默认属性；占用数 = 实际任职数，超编有告警且可配置拦截。

### 5.3 人员主数据（Worker Profile）

- **功能描述**：统一的"员工/Worker"主数据，覆盖所有用工类型。
- **关键能力**：
  - **统一 Worker 模型**：正式员工、合同工、派遣工、兼职、退休返聘、申请人统一建模；
  - 多页签档案（基本信息 / 任职 / 合同 / 教育履历 / 家庭 / 培训 / 绩效等）；
  - **EAV 自定义字段**：标准字段 + 客户自定义字段，支持必填/类型/下拉/正则/敏感脱敏；
  - 生命周期状态（在职 / 试用 / 停薪留职 / 离职 / 黑名单）与生效日期。
- **业务流程要点**：档案结构（页签/分组/字段）可由 HR 配置，无需改代码。
- **验收线索**：HR 可自助新增一个档案页签与自定义字段并立即生效；敏感字段（身份证/薪资）按权限脱敏。

### 5.4 汇报关系（Reporting Lines）

- **功能描述**：维护员工与上级/组织的多元汇报关系。
- **关键能力**：
  - 三类汇报线：**实线（Solid）** / **虚线（Dotted）** / **职能线（Functional）**；
  - 矩阵任职（一人多岗、多维度归属、分配比例 Allocation）；
  - 上级链（manager chain）计算与展示。
- **业务流程要点**：汇报线变更随人事事件（调动）联动；虚线/职能线可由矩阵组织自动派生或手工维护。
- **验收线索**：某员工可同时有 1 条实线 + N 条虚线/项目线；组织图可切换"仅实线 / 含虚线"视图。

### 5.5 组织版本与快照（Org Versioning）

- **功能描述**：以"调整单 + 快照"方式管理组织的时序变化，支持任意时点回看。
- **关键能力**：
  - **生效日期（Effective Dating）**：组织/任职变更带生效日，未来变更可预排；
  - **调整单（Change Request）**：Rename / Move / NewManager / Close 等变更类型，草稿 → 审批 → 生效；
  - **快照（Snapshot）**：生效时生成全量组织快照；
  - **As-of 回看**：按任意历史日期查看当时组织结构。
- **业务流程要点**：审批可配置单级/多级；生效时重建层级闭包并做合规校验（如关闭前防孤儿）。
- **验收线索**：选择"2025-01-01"可还原当日组织全貌；未来调整单在生效日前不影响现状。

### 5.6 维度管理（Dimensions）

- **功能描述**：以多维度切片组织，突破单一行政树。
- **关键能力**：
  - 维度类型：法人（Legal）/ 职能（Functional）/ 地理（Geographic）/ 矩阵（Matrix）等；
  - 同一组织单元可在多个维度归属；维度可配置（新增/编辑/着色）；
  - 维度切换即切换组织图主轴（如"按成本中心看" vs "按矩阵看"）。
- **业务流程要点**：维度是组织图与报表的共同维度键。
- **验收线索**：管理员新建"区域"维度并挂接部门后，组织图可一键切换主轴。

### 5.7 人事事件（Personnel Actions）

- **功能描述**：以配置化业务流程驱动员工生命周期事件。
- **关键能力**：
  - 事件类型：入职、转正、调动、晋升、降职、离职、并发雇佣（Concurrent Employment）、借调；
  - **配置化业务流程（BP Framework）**：每类事件可配置步骤、参与者、审批流、生效规则；
  - 事件联动：自动切分任职（Job 半开区间）、同步主数据、触发编制与汇报线变更。
- **业务流程要点**：事件与组织版本（5.5）、岗位（5.2）、汇报线（5.4）强联动。
- **验收线索**：发起"调动"后，按配置流程自动经经理/HR 审批并生成新任职记录，旧任职自动关闭。

### 5.8 员工与经理自助（ESS / MSS）

- **功能描述**：员工与经理在权限范围内自助操作，减少 HR 事务量。
- **关键能力**：
  - **ESS**：查看/维护个人档案、修改联系方式、发起证明申请、查看团队与汇报关系；
  - **MSS**：团队花名册、审批下属请求、查看团队编制/空缺、发起人事事件；
  - 移动优先：移动端可完成查看、审批、发起等关键动作。
- **业务流程要点**：自助动作受数据范围与字段权限约束。
- **验收线索**：经理在手机上审批下属的调动请求；员工修改手机号后触发二次校验。

### 5.9 搜索优先导航与全局搜索（Workday 特色）

- **功能描述**：以全局搜索为第一入口，直达任意对象。
- **关键能力**：
  - 全局搜索（⌘K / Ctrl+K）覆盖 人 / 组织 / 岗位 / 事件；
  - 搜索结果按对象类型分组的直达卡片；
  - 保留顶部总菜单 + 左侧子菜单作为结构化兜底导航。
- **业务流程要点**：搜索即操作入口（搜索到人 → 打开抽屉 → 就地操作）。
- **验收线索**：输入员工姓名/工号/部门，3 步内到达目标对象的操作界面。

### 5.10 分析与仪表盘（Analytics）

- **功能描述**：组织人事的内嵌分析，事务-分析同源。
- **关键能力**：
  - 核心人事驾驶舱：组织总数、人数、编制满编率、离职率、关键岗位空缺；
  - 组织/编制/人员 KPI 卡片 + 下钻；
  - 报表与原生交易同库，报表行可下钻回交易并就地处理。
- **业务流程要点**：分析权限继承数据安全配置。
- **验收线索**：在编制报表中点击"超编部门"可直接下钻到该部门岗位占用明细并操作。

### 5.11 权限与数据安全（Security）

- **功能描述**：统一安全模型，保护敏感人事数据。
- **关键能力**：
  - **角色（Role）+ 数据范围（Data Scope）**：全集团 / 某子树 / 本人；
  - **字段级脱敏**：身份证、薪资、联系方式等按权限 masking；
  - **统一安全（secure data, not fields）**：权限挂在数据对象上，跨入口（Web/移动/API）一致生效；
  - 完整审计日志（谁、何时、改了什么）。
- **业务流程要点**：所有列表/详情查询强制叠加数据范围权柄。
- **验收线索**：无 PII 权限的用户看到邮箱为 `••••••`；越权访问被拒绝并记录。

### 5.12 全球化与本地化（Globalization）

- **功能描述**：支持多国家/区域的合规与本地化。
- **关键能力**：
  - 可插拔本地化框架：语言、币种、日期格式、地址/证件格式；
  - 国家/区域特定的合规字段与流程（如 GDPR、用工合规）；
  - 多语言档案与界面。
- **业务流程要点**：核心模型全球一致，本地差异走配置而非分支代码。
- **验收线索**：同一平台切换国家后，证件字段、日期格式、合规提示自动适配。

## 6. 界面与交互风格规范

> 融合 SF 的企业级可信与 Workday 的消费级轻盈。本章给出**可落地的视觉与组件规范**，供设计与前端直接消费。

### 6.1 信息架构（IA）

- **顶栏（Topnav）**：5 大模块总菜单（核心人事 / 薪资 / 考勤 / 报表 / 系统设置），hover 出子菜单；
- **左栏（Sidebar）**：按当前模块展示**上下文子菜单**并高亮当前项（组织 / 矩阵 / 人员 / 维度 / 组织版本 / 通用查询）；
- **全局搜索**：顶栏右侧常驻搜索入口（⌘K），作为第一导航（Workday 特色）；
- **数据范围标识**：顶栏展示当前可见范围（全集团 / 某子树 / 本人）。

### 6.2 布局原则

- **主工作区 + 抽屉式详情**：列表/组织图为主，点击节点从右侧抽屉展开详情与就地操作，减少页面跳转；
- **响应式栅格**：桌面三栏（顶栏/左栏/主区），移动端折叠为抽屉 + 底部 Tab；
- **移动优先**：关键查看/审批/发起在移动端完整可用。

### 6.3 视觉规范（混合配色）

建议采用"企业蓝主色 + 中性灰阶 + 单一暖色强调"，兼顾可信与轻盈：

| 令牌             | 取值（建议）    | 用途             |
| -------------- | --------- | -------------- |
| `--blue`（主色）   | `#0875E1` | 主操作、链接、选中态     |
| `--accent`（强调） | `#DF9A2C` | 关键提示、KPI 高亮    |
| `--green`      | `#0E8A6D` | 成功 / 在职 / 满编   |
| `--red`        | `#C0392B` | 危险 / 离职 / 超编告警 |

- **圆角**：卡片 8–12px，按钮 6–8px，体现轻盈；
- **间距**：8px 栅格基线，留白充足；
- **字体**：系统无衬线（中文优先 PingFang / 微软雅黑），正文 14px，标题 18–22px；
- **主题**：默认浅色，预留深色主题变量。

## 7. 数据模型要点（概念层）

> 仅列核心实体、关键字段与关系，不写完整 DDL。命名尽量与行业及现有实现一致以降低歧义。


| 实体 | 作用 | 关键字段 |
|---|---|---|
| **Worker / Employee** | 员工/Worker 主数据 | WorkerId, 工号, 姓名, 用工类型, 状态, 生命周期 |
| **Organization / OrgUnit** | 组织单元 | OrgUnitId, 编码, 名称, 类型, 层级, 上级, 负责人, 编制预算, 状态 |
| **OrgHierarchy** | 多维度层级关系 | 维度Id, 父, 子, 深度, 关系类型(实/虚/职能/共享) |
| **Dimension** | 组织维度 | DimensionId, 编码, 名称, 类型(法人/职能/地理/矩阵), 着色, 是否主维度 |
| **Position** | 岗位（需求实例） | PositionId, 所属组织, 职级, FTE, 是否管理岗, 关键岗位, 占用员工 |
| **Job** | 职位（职级/职能类别） | JobId, 职能族, 职级, 薪酬带宽 |
| **Assignment** | 任职（一人多岗/矩阵） | WorkerId, 组织, 维度, 类型(主/副/虚线/项目), 分配比例, 是否主任职 |
| **ReportingLine** | 汇报关系 | WorkerId, 上级Id, 线类型(实/虚/职能), 维度, 权重 |
| **Employment / JobHistory** | 雇佣与任职历史 | 雇佣Id, 类型, 起止, 状态；任职历史(半开区间, IsCurrent) |
| **HeadcountPlan** | 编制 | 组织, 财年, 计划, 已占, 预算 |
| **OrgVersion / Change / Snapshot** | 组织版本与快照 | 版本Id, 状态(草稿/生效/取消), 变更类型, 生效日, 快照 |
| **PersonnelAction** | 人事事件 | 事件Id, 类型, 参与者, 审批流, 生效日, 联动对象 |
| **ProfileTab / FieldDef / CustomValue** | 可配置档案 + EAV | 页签/分组/字段定义；自定义值(按类型分列) |
| **安全** | RBAC + 数据范围 | 角色, 权限, 用户角色, 数据范围(全集团/维度/组织/本人), 字段脱敏标记 |

**关系要点**：Worker ←(Assignment/ReportingLine)→ OrgUnit（多对多，带维度）；OrgUnit 经 OrgHierarchy 自关联成树；Job 经 Position 关联 OrgUnit；任职历史以半开区间表达时序。

## 8. 开放问题与待澄清决策点

> 这是澄清文档的核心。每项给出**选项**与**建议**，需评审拍板。

| # | 决策项 | 选项 | 建议 |
|---|---|---|---|
| Q1 | 岗位制 vs 职位制 | A 仅职位(Job) / B 岗位(Position)+职位分离(SF/WD 思路) | **B**：岗位治理更严谨，支持编制与关键岗位 |
| Q2 | 维度是否可配置 | A 固定维度 / B 管理员可增删维度 | **B**：组织形态差异大，需灵活 |
| Q3 | 组织版本粒度 | A 仅整组织快照 / B 调整单级(更名/移动/新主管/关闭) | **B**：变更可审批、可回溯 |
| Q4 | 审批流复杂度 | A 单级 / B 多级可配置(BP Framework) | **B**（首期可单级，模型留多级） |
| Q5 | 移动端优先级 | A 桌面优先 / B 移动优先(WD) | **B**：自助与审批移动化是趋势 |
| Q6 | 本地化首期范围 | A 仅中国 / B 多国家框架+首期中国 | **B**：建可插拔框架，首期中国 |
| Q7 | 自助(ESS/MSS)范围 | A 仅查看 / B 查看+发起+审批 | **B**：降本关键 |
| Q8 | 与其他模块接口边界 | A 仅定义 / B 定义+约定事件钩子 | **B**：定义人事事件向外发消息的机制 |
| Q9 | 档案自定义字段能力 | A 固定字段 / B EAV 可配置 | **B**：降低二开 |
| Q10 | 分析是否首期内 | A 仅基础报表 / B 驾驶舱+下钻 | **B**（轻量驾驶舱，验证同源价值） |
| Q11 | 统一 Worker 模型范围 | A 仅员工 / B 含派遣/合同/退休/申请人 | **B**：单一事实源要求 |
| Q12 | 汇报线维护方式 | A 仅随事件联动 / B 可独立维护虚线/职能线 | **B**：矩阵组织需手工维护 |
| Q13 | 搜索优先落地程度 | A 仅列表内搜索 / B 全局搜索直达(WD) | **B**：体验差异点 |
| Q14 | 数据规模目标 | A 千级 / B 万级~十万级(性能导向) | **B**：按 5 万员工/千并发设计 |
| Q15 | 视觉主题 | A 仅浅色 / B 浅色+深色双主题 | **B**（首期浅色，预留深色） |
